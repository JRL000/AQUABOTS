## 1. Camera (Jetson Orin Nano, IMX219 CSI)

### Root cause
JetPack 6.2 (L4T R36.4.7) broke OpenCV's camera frame access. `cv2.VideoCapture` with the `nvarguscamerasrc` pipeline returns black frames because Argus no longer exposes a DMA file descriptor (`dmabuf_fd=-1`), and OpenCV's GStreamer backend calls `NvBufSurfaceFromFd()` on every frame and silently fails. Pure OS regression — nothing changed on our end.

### Fix
Replaced `cv2.VideoCapture` with the PyGObject GStreamer bindings (`gi.repository.Gst`) in `/home/mayra/webrtc_jetson.py`. The new code pulls samples from the appsink with `sink.emit('pull-sample')` and maps them with `buf.map(Gst.MapFlags.READ)`. This bypasses OpenCV's broken code path entirely.

### Secondary issue discovered
After reseating the hull, the camera still came up black. Kernel dmesg showed `imx219` I2C probe failing with `-110 ETIMEDOUT` and then `-121 EREMOTEIO`. The CSI ribbon cable was physically disconnected on the sensor end. Fully reseated both ends (contacts toward the board on each side, latches closed) and full power-cycled. On the second attempt the kernel bound `imx219` cleanly and the stream came up.

### Recovery procedure (save this)
If the camera goes black again:
1. Check the CSI ribbon cable first — both ends must be fully seated and latched, contacts facing the board.
2. Full power-cycle, not just reboot, so the kernel re-probes the IMX219 over I2C.
3. Verify with `sudo dmesg | grep imx219` — expect a `bound` line and no `board setup failed`.
4. Check `systemctl --user status webrtc.service` on the Jetson.
5. Do NOT start `sudo systemctl start webrtc_jetson.service`. The correct service is the user-level `webrtc.service`; the system-level one conflicts with it and fails with `Failed to create CaptureSession`.

### Deploy status
Fix pushed, service running, stream verified. 04-11-2026.

## 6. ESP32 ↔ Jetson Sensor Bridge (IF-3) — Built Today

### Context
Jamie's Arduino prototype (`Claude/project-docs/sensors-code.txt`) reads three sensors and writes `TEMP:%.2f,SAL:%.3f,PH:%.2f\n` over USB serial every 3 s. Jetson side (`jetson/app.py:read_esp32`) already parses that exact format and folds it into the telemetry JSON broadcast. Gap: no ESP32-side implementation in the ESP-IDF firmware.

### What was written
**`firmware/main/sensor_bridge.h`** (new)
- Every pin, ADC channel, UART port, baud, and task timing is a `#define` at the top of the header. One-file remap.
- Public API: `sensor_bridge_init()`, `sensor_bridge_start()`, `sensor_bridge_stop()`, `sensor_bridge_get_snapshot()`, per-value getters.
- `sensor_bridge_snapshot_t` struct for whole-state copies.

**`firmware/main/sensor_bridge.c`** (new, ~480 lines)
- DS18B20 on GPIO 4 via the Espressif `onewire_bus` + `ds18b20` managed components. Iterates the bus, takes the first device, sets 12-bit resolution.
- TDS on ADC1 channel 0 (GPIO 1) via the ESP-IDF 5.x oneshot ADC API with curve-fitting calibration when efuse data is present, raw-scaled fallback when it isn't. 16 samples averaged per reading.
- Salinity math ported verbatim from Jamie's Arduino code — 0.02 temperature-compensation coefficient, cubic polynomial → EC → ppm → PPT, with guards for negative values and extreme temperatures.
- Atlas EZO pH on UART1 (GPIO 16 RX / GPIO 17 TX) at 9600 baud. Passive drain — accumulator buffer, newline-terminated, validates 0 < pH < 14, keeps last valid reading between ticks with a stale-age warning at 10 s.
- Jetson output on UART2 (GPIO 47 TX / GPIO 48 RX) at 115200 baud. Pushed off GPIO 19/20 (native USB) and GPIO 43/44 (USB-UART bridge / swarm console) so the payload link is independent of both.
- One FreeRTOS task, 3-second period via `vTaskDelayUntil`. Writes `TEMP:%.2f,SAL:%.3f,PH:%.2f\n` to the Jetson UART each cycle.
- Best-effort init: only the Jetson UART is mandatory. Any missing sensor logs a warning and reports 0 / cached value without killing the task.

**`firmware/main/main.c`** (edit)
- `#include "sensor_bridge.h"` added alongside the other module headers.
- `sensor_bridge_init()` called after `avoidance_init()`.
- `sensor_bridge_start()` called after `avoidance_start()`.
- Module startup order comment updated to list item 11.

**`firmware/main/CMakeLists.txt`** (edit)
- `sensor_bridge.c` registered in `SRCS`.

**`firmware/main/idf_component.yml`** (new)
- Declares `espressif/onewire_bus ^1.0.2` and `espressif/ds18b20 ^0.1.3` managed-component dependencies. `idf.py build` will fetch these into `firmware/managed_components/` on first run.

### Deferred until hardware is back
- `idf.py set-target esp32s3` + `idf.py build` (not runnable without the board).
- Pin verification against the physical ESP32-S3 variant in the hull. GPIO 48 is the WS2812 RGB LED on DevKitC-1 v1.1; if that turns out to be the board in play, bump `SENSOR_BRIDGE_JETSON_UART_RX_GPIO` to 15 or 21.
- Physical wiring check against `AQUABOTS_WIRING_GUIDE.md`. Note: the wiring guide currently lists pH as I²C (S8 SDA/SCL pair in the CAT6 bundle), but both Jamie's Arduino code and the new `sensor_bridge.c` use UART. The Atlas EZO pH module supports both; whichever mode is physically wired is the one that has to match. Flag this before soldering anything.
