## Architecture (final, please read before troubleshooting)

ESP32 swarm framework = coordination plane. Jetson coordinator = execution plane. They communicate over the existing sensor_bridge UART.

```
                ESP-NOW radio between boats
        ┌──────────────────────────────────┐
        │ (membership, leader election,    │
        │  formation math, GPS_ANCHOR)     │
        └──────────────────┬───────────────┘
                           │
                  ESP32-S3 swarm node
                           │
                           │ swarm_bridge UART
                           │ (existing 115200, GPIO 43/44)
                           │ Tag-prefixed lines:
                           │   ESP32→Jetson: SWARM_ROLE / SWARM_TARGET /
                           │       SWARM_LEADER_GPS / SWARM_FORMATION /
                           │       SWARM_STOP
                           │   Jetson→ESP32: ANCHOR_GPS / SET_FORMATION /
                           │       SWARM_ENABLE
                           ▼
                   Jetson swarm_coordinator
                           │
                           │ MAVLink SET_POSITION_TARGET_GLOBAL_INT
                           │ in GUIDED mode
                           ▼
                       Pixhawk
                           │
                           ▼
                       motors + servos
```

### Jetson side (`jetson/`)
- `swarm_protocol.py` — Python mirror of `swarm_bridge.h` constants, `parse_line`, `encode_anchor_gps`/`encode_set_formation`/`encode_enable`.
- `swarm_coordinator.py` — `SwarmCoordinator` class (mutex-protected `SwarmState`). `feed_pixhawk_gps()` ingests local GPS. `feed_serial_line()` consumes tagged lines from the ESP32. `_tick_loop` at 10 Hz handles leader-anchor TX (1 Hz when leader+enabled+3D-fix) and stale-leader-GPS HOLD trip (>5 s). `_maybe_recompute_and_command` runs `offset_to_latlon` (small-angle flat-earth) and uploads the waypoint via the host-supplied `upload_waypoint(lat, lon, heading)` callback. ALSO computes `target_latlon` even when not enabled, so the GUI can show the ghost slot as a preview.
- `app.py` integration:
  - `_TcpLink` — duck-types `serial.Serial` enough for `read_esp32`. **Important gotcha:** uses raw `socket.recv()` with manual line buffering, NOT `socket.makefile('rb')`. The buffered-file version got into a permanently-poisoned state on socket timeout that raised `OSError("cannot read from timed out object")` — indistinguishable from a real disconnect — and that caused the connection to drop every second. Found 2026-04-25 evening.
  - `_open_esp32_link` — picks serial vs TCP based on `AQUABOT_ESP32_TCP=host:port` env var.
  - `read_esp32` — refactored to dispatch lines by family (legacy `TEMP:...` → existing temp/sal/ph globals, swarm-tagged → `swarm.feed_serial_line()`) and to drain `swarm.get_outbound_line()` back to the link.
  - `upload_swarm_waypoint(lat, lon, heading_deg)` — sends `SET_POSITION_TARGET_GLOBAL_INT` with type_mask = ignore everything except position + yaw, in `MAV_FRAME_GLOBAL_RELATIVE_ALT_INT`.
  - `swarm_geofence_check(lat, lon)` — runs even-odd ray-cast against `_fence_polygon_latlon` IF `_fence_enabled`; both globals are populated by `upload_fence_sync` and `set_fence_enable`.
  - WS actions: `swarm_enable` (admin-gated; pre-arm = 3D fix + HOME_SET unless mock mode), `swarm_set_pattern` (NO admin needed — config not motion), `mock_set_scenario` (admin), `mock_set_members` (admin).
  - Mock subprocess auto-spawn when `AQUABOT_ESP32_TCP` set, with `--scenario` and `--members N`.
  - `_mock_pixhawk_feeder` — fake Pixhawk feed for dev. When swarm mode is enabled, lerps the boat toward its assigned `target_latlon` at 0.5 m/s in 0.2 s ticks so the simulation visibly moves.
  - Pixhawk reader extended: `NAV_CONTROLLER_OUTPUT` (target_bearing, nav_bearing, wp_dist, xtrack_error), `ATTITUDE` now also captures roll/pitch.
  - Telemetry broadcast added: `NAV_TARGET_BEARING`, `NAV_DESIRED_BEARING`, `NAV_WP_DIST_M`, `NAV_XTRACK_ERROR_M`, `NAV_HEADING_ERROR` (computed: `((target_bearing - heading + 540) % 360) - 180`), `ROLL`, `PITCH`, `STEER_DEFLECTION_PCT`, `THROTTLE_DEFLECTION_PCT`, `MOCK_MODE`, `MOCK_SCENARIO`, `MOCK_SCENARIOS`, `MOCK_MEMBERS`, `SWARM` (full coordinator snapshot).

## Bug found and fixed late in the session

The `_TcpLink` originally used `socket.makefile('rb')` for `readline()`. On socket timeout, the buffered file object enters a permanently-poisoned state and any subsequent read raises `OSError("cannot read from timed out object")` — which is indistinguishable from a real disconnect. Result: the TCP connection to the mock dropped every second, which meant `SET_FORMATION` lines queued by `swarm_set_pattern` rarely reached the mock before the connection reset. Symptom: pattern + spacing changes appeared to do nothing (only Wedge "worked" because that was the mock's startup default).

Fix: rewrote `_TcpLink` to use raw `socket.recv()` with manual line buffering. `socket.timeout`/`TimeoutError` returns `b""` (transient); a 0-byte recv or other `OSError` raises (real disconnect). Verified end-to-end: `swarm.pattern` and `spacing_mm` now propagate to telemetry within ~1 s of clicking a pattern button.
